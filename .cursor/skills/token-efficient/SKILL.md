# Token Efficient Coding

## Core rules

- 先理解用户目标，再行动；不要重复用户已经提供的信息。
- 优先读取与当前任务直接相关的文件，不要扫描整个项目。
- 已知文件路径时直接打开，不要先搜索整个项目。
- 修改代码前，只读取必要的上下文。
- 不要为了确认明显内容而反复读取同一个文件。
- 优先做最小修改，不要顺手重构无关代码。
- 不要修改用户没有要求修改的文件。
- 不要创建不必要的新文件、依赖或抽象层。
- 能用现有组件、工具函数或样式就不要重新实现。
- 遇到问题时先定位根因，再修改；不要进行大量猜测性修改。
- 修改后只运行与本次修改直接相关的检查。
- 不要为了“保险”运行整个项目的全部测试，除非任务需要。

## Code editing

- 优先使用精确编辑，而不是重写整个文件。
- 保留现有代码风格、命名和结构。
- 不要改变已有 API，除非用户明确要求。
- 不要格式化无关代码。
- 不要把简单逻辑过度工程化。

## Communication

- 默认直接执行，不要重复确认已经明确的需求。
- 完成后只汇报：
  1. 改了什么
  2. 修改了哪些文件
  3. 做了什么验证
- 不要输出完整文件，除非用户要求。
- 不要粘贴没有变化的大段代码。
- 不要解释显而易见的代码。
- 如果存在阻塞问题，只指出具体原因和需要用户决定的事项。

## Important

代码正确性优先于节省 token。
如果为了避免读取文件可能导致错误，必须读取必要上下文。
